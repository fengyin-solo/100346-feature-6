# 森林防火巡护管理系统

面向森林火险监测、巡护任务调度、防火设施维护与应急响应指挥的林区防火管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `forest-fire-patrol:entries:v2` 这一项，或调用 `resetModule(模块)`。

## 扑火队伍：林场权限边界与出动规则

顶栏可切换「值班林场」（青松岭 / 白桦林 / 红松岗），扑火队伍按所属林场隔离写权限：

- **权限边界**：仅队伍**当前所属林场**的值班台能改队伍编号、队长姓名、集结半径，以及下达出动、
  休整、撤回；其它林场的队伍在列表里只读（动作按钮禁用）。拦截同时做在
  `local-service.ts` 数据层，绕过页面直接提交也会被拒并返回越权提示。
- **冲突出动命令按接令时间处理**：同一支队伍的出动命令先到先受理（命令台账见
  `src/data/command-ledger.ts`，记录首条命令的林场、值班员、接令时刻），30 秒窗口内后到的
  冲突命令一律驳回并告知首条接令时间；不按队伍距离，因为纯前端无可靠坐标，接令时间可追溯。
- **调岗留痕**：跨林场调岗只更新「所属林场」，并在「归属变更记录」追加一条留痕；
  「历史归属林场」保持建队时的原林场不变。调岗后写权限随新归属走，原林场变为只读。
- **出动联动火情报告**：出动确认成功后，火情报告模块（其它入口）的「待出警」清单自动新增
  一份关联该队伍编号的报告。
- **两台终端同时提交只落库一次**：命令台账以「队伍+动作+秒级时间」为指纹做幂等占坑（模拟
  后端唯一约束/行锁），第二台终端拿到 `duplicated` 结果且不写库，联动的火情报告也只有一份；
  写库前强制重读 `localStorage`，避免本标签页旧缓存覆盖另一终端的新数据。

`npm run verify`（在 `frontend/` 下）会用 Node 模拟两个林场 × 两台终端，跑通越权拦截、
幂等、接令时间仲裁、调岗历史归属等 21 项断言。
